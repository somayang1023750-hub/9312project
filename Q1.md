# Q1: Earliest-Connection Queries

This report analyses the implementation of `EarliestConnectionQuery.query(n, L, Q)` in [Q1.ipynb](Q1.ipynb).

## 1. Notation and approach

Let $n$ be the number of vertices, $m=|L|$ the number of inserted edges, and $q=|Q|$ the number of query pairs. Edge $L[t-1]$ arrives at time $t$. Let $\alpha(n)$ denote the inverse Ackermann function, taken to be at least 1 for small $n$.

The algorithm processes the stream once, builds a **component merge forest**, and answers each pair using a lowest common ancestor (LCA) query. A heavy-light decomposition supports these queries with linear auxiliary space.

The analysis uses the usual unit-cost model for vertex IDs, array indices and integer labels. Python list appends and removals from the end take amortised constant time. The DSU bounds below are also amortised over the operation sequence.

## 2. Algorithm

### 2.1 Process the insertion stream

Initially, every vertex is an isolated component and a leaf of the merge forest. A leaf's time label is 0. The implementation maintains:

| Structure | Purpose |
| --- | --- |
| `dsu`, `size` | Current components, using path halving and union by size |
| `top[r]` | Historical root representing the component with DSU root `r` |
| `parent`, `left`, `right` | Parent and binary-child links in the merge forest |
| `time[x]` | Insertion time of the union represented by node `x` |
| `leaf_count[x]` | Number of original vertices below node `x` |

For the edge $(u,v)$ arriving at time $t$:

1. Find its two current DSU roots.
2. If they are equal, skip the edge: it does not change connectivity.
3. Otherwise, create a new history node labelled $t$. Its children are the two components' current historical roots. Set both children's historical parent to the new node and record the sum of their leaf counts.
4. Union the DSU components by size and update the winning root's `top` entry.

DSU parent links and historical parent links are separate. Path halving can therefore accelerate DSU operations while preserving the merge history. Each final historical root is its own parent.

If the final graph has $c$ connected components, including isolated vertices, there are exactly $r=n-c$ successful unions. The history contains

$$
H=n+r=2n-c
$$

nodes and $2r$ child links. These equations also give $H=0$ for an empty graph. In particular, history storage is $O(n)$, even if many inserted edges create cycles.

### 2.2 Prepare heavy-light LCA queries

At each internal history node, choose the child with the larger `leaf_count` as the heavy child, breaking ties by the existing child order. The other child is light. A heavy child continues its parent's chain; a light child starts a new chain.

An iterative DFS records each history node's depth and chain head, and the final component root for every original vertex. It visits each history node once. The explicit stack handles a history of linear depth without recursive calls.

To find an LCA, repeatedly compare the depths of the two chain heads and move the vertex with the deeper head to that head's parent. When both remaining nodes are in the same chain, the shallower one is their LCA.

### 2.3 Answer pairs in input order

For each pair $(u,v)$:

- If $u=v$, append 0.
- If their final component roots differ, append $-1$.
- Otherwise, append the time label of their LCA in the merge forest.

The returned list follows the order of `Q`. Repeated pairs are answered independently. Neither input list is modified. If `Q` is empty, the method returns immediately and does not construct the forest.

## 3. Correctness

### Lemma 1: The history represents the components after every insertion

Initially, both DSU and the history represent singleton components. Suppose this is true immediately before an edge arrives. If its endpoints are already connected, the edge changes no component, and skipping it preserves the representation. Otherwise, the edge joins exactly two components. Creating their common parent and updating DSU represents precisely that union. No other component changes. The invariant follows by induction over the stream.

### Lemma 2: The LCA gives the first connection time

Consider distinct vertices $u$ and $v$ in the same final component, and let $x$ be their history LCA. They lie in different child subtrees of $x$. By Lemma 1, just before the union labelled `time[x]`, those subtrees represent separate connected components. At that union, a new edge joins them. Thus $u$ and $v$ become connected at `time[x]` and were not connected earlier.

If the vertices have different final roots, they never become connected, since edge insertion cannot destroy an existing connection. A vertex is connected to itself from the initial state, giving time 0.

### Lemma 3: Heavy-light navigation returns the LCA

When the two chain heads differ, moving above the deeper head cannot skip the LCA. If the LCA were inside that head's chain, the other vertex would either be on the same chain or have a chain head below the LCA, and therefore deeper than the head chosen for the jump. Once the remaining vertices share a chain, they are on one ancestor path, so the shallower vertex is their LCA.

Combining these lemmas proves that every returned value is the required earliest connection time, 0, or $-1$.

## 4. Time complexity

### 4.1 Stream processing and preprocessing

| Work | Cost | Reason |
| --- | --- | --- |
| Initialise DSU and leaf arrays | $\Theta(n)$ | Every vertex is represented, including isolated vertices |
| Read all stream edges and perform DSU operations | $O(m\alpha(n))$ | Two finds per edge and at most one size-based union |
| Create history nodes and update links, counts and `top` | $O(r)$ | A constant number of appends and assignments per successful union |
| Initialise decomposition arrays and scan history roots | $O(H)$ | Arrays and root checks cover all history nodes |
| Compute depths, chain heads and final component IDs | $O(H)$ | Each history node is visited once |

Since $r\leq n$ and $H\leq 2n$, total preprocessing takes

$$
T_{\mathrm{pre}}=O\bigl(n+m\alpha(n)\bigr).
$$

The $n$ term remains necessary when the graph has many isolated vertices or no edges. Auxiliary-array initialisation and maintenance are included in this bound.

### 4.2 One pair after preprocessing

For a light child $y$ of a node $x$,

$$
\operatorname{leaf\_count}(y)\leq
\frac{\operatorname{leaf\_count}(x)}{2}.
$$

Therefore a root-to-leaf path contains at most $\lfloor\log_2 n\rfloor$ light edges when $n\geq1$. Each upward chain-head jump crosses one light edge, at least doubling the relevant subtree's leaf count. There are $O(\log(n+1))$ jumps over the two paths, each with constant work.

A pair in one final component therefore takes $O(\log(n+1))$ time. Identical endpoints and vertices in different final components take $O(1)$ time. No graph traversal is performed for a pair.

### 4.3 Entire batch and repeated calls

Appending all $q$ answers costs $O(q)$ amortised time. For a nonempty query list, the complete method call takes

$$
T(n,m,q)=O\bigl(n+m\alpha(n)+q\log(n+1)\bigr).
$$

The $O(\log(n+1))$ bound above is for a pair **after preprocessing**. Calling `query(n, L, [(u, v)])` still rebuilds the history and decomposition; its worst-case bound is $O(n+m\alpha(n)+\log(n+1))$.

For $q>0$, charging the whole batch evenly to its pairs gives an amortised per-pair bound of

$$
O\left(\frac{n+m\alpha(n)}{q}+\log(n+1)\right).
$$

There is no persistent cache between calls. For $b$ nonempty calls on the same graph, containing $q_{\mathrm{total}}$ pairs altogether, the total bound is

$$
O\bigl(b(n+m\alpha(n))+q_{\mathrm{total}}\log(n+1)\bigr).
$$

An empty query list is a separate fast path taking $O(1)$ time, including the valid case $n=0$.

## 5. Space complexity

| Category | Space | Contents |
| --- | --- | --- |
| Caller-owned inputs | $O(m+q)$ | Edge and pair lists; `n` is a scalar |
| DSU workspace | $O(n)$ | `dsu`, `size`, `top` |
| Historical forest | $O(n)$ | Five arrays of length $H$: parents, two children, times and leaf counts |
| Decomposition and traversal | $O(n)$ | Depths, heads, vertex component IDs and the explicit DFS stack |
| Returned answer list | $O(q)$ | One integer per pair |

Excluding the input lists and returned answers, peak auxiliary data-structure space is **$O(n)$**. Including the answer list gives $O(n+q)$ additional space, and including the caller-owned inputs gives $O(n+m+q)$ total space. The empty-query fast path uses only $O(1)$ additional space.

## 6. Worked example and boundary cases

For the first example in the specification,

```text
n = 7
L = [(0,1), (2,3), (1,2), (4,5), (3,4), (0,3), (5,6)]
Q = [(0,4), (1,6), (0,2), (2,6), (5,3)]
```

Write $H_t$ for the historical node created at insertion time $t$; this notation is independent of its array index.

| Time | Edge | History update | Leaves below the new node |
| --- | --- | --- | --- |
| 1 | `(0,1)` | $H_1$ joins leaves 0 and 1 | 2 |
| 2 | `(2,3)` | $H_2$ joins leaves 2 and 3 | 2 |
| 3 | `(1,2)` | $H_3$ joins $H_1$ and $H_2$ | 4 |
| 4 | `(4,5)` | $H_4$ joins leaves 4 and 5 | 2 |
| 5 | `(3,4)` | $H_5$ joins $H_3$ and $H_4$ | 6 |
| 6 | `(0,3)` | No new node: the endpoints are already connected | — |
| 7 | `(5,6)` | $H_7$ joins $H_5$ and leaf 6 | 7 |

The resulting historical tree is:

```text
H7 (time 7)
|-- H5 (time 5)
|   |-- H3 (time 3)
|   |   |-- H1 (time 1)
|   |   |   |-- 0
|   |   |   `-- 1
|   |   `-- H2 (time 2)
|   |       |-- 2
|   |       `-- 3
|   `-- H4 (time 4)
|       |-- 4
|       `-- 5
`-- 6
```

The five LCAs have time labels `5, 7, 3, 7, 5`, so the output is `[5, 7, 3, 7, 5]`. The cycle edge at time 6 does not alter the earliest connection times.

For `n = 5`, `L = [(0,1), (1,2), (3,4)]`, the pairs `[(0,2), (2,3), (4,4)]` return `[2, -1, 0]`. With no edges, distinct vertices remain in separate singleton trees, and identical vertices still return 0. Repeated pairs produce repeated answers in their original positions.
